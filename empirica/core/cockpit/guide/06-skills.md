# 6. Skills

## What a skill is

A skill is a written routine the practitioner can load when it needs it: how to run a
review, how to plan a large job, how to clean up its memory, how to send a message to
another practice. It is like handing a colleague the team's checklist for a job instead of
hoping they remember it.

Skills have names that start with a slash, for example `/epistemic-gardening` (tidying the
practice's notebook, page 9).

## Who loads them

Mostly the practitioner does, on its own, when the situation calls for one: it sees that
you asked for a careful review and loads the review checklist first. You will notice it in the
conversation as a skill being loaded.

You can also ask in plain words: "use the review routine for this", "plan this properly
first", "tidy up your notes". If you know the name, typing it works too.

## When to ask for a skill yourself

- The job has a known routine and you want it followed: reviews, planning, clean-ups,
  writing to another practice.
- The practitioner is improvising something the team already has a method for.
- You want consistent results across practitioners: the same skill gives the same steps.

If you are not sure which skill fits, ask: "Is there a skill for this?" The practitioner
can list the ones it has and say which it would use.

## Skills are shared

Skills are maintained centrally and updated for everyone. When a skill improves, every
practice gets the better version with the next update (**update Empirica on this machine** in the cockpit's menu, page 10).
